## การยืนยันตัวตน {#authentication}
:::info

เอนด์พอยต์พื้นฐานของ REST API:
`https://api.waanx.com`

### เลือกประเภทคีย์ API ของคุณ
**คีย์ API ที่ระบบสร้างให้**: คีย์ API ที่ระบบของ WaanX สร้างขึ้นจะใช้การเข้ารหัสแบบ HMAC โดยคุณจะได้รับ
คู่คีย์สาธารณะและคีย์ส่วนตัว โปรดปฏิบัติกับคู่คีย์นี้เสมือนเป็นรหัสผ่านและเก็บรักษาไว้อย่างปลอดภัย

> ทำตามสคริปต์ตัวอย่างของ HMAC เพื่อดำเนินขั้นตอนการเข้ารหัสให้เสร็จสมบูรณ์

**คีย์ API ที่สร้างขึ้นเอง**: คีย์ API ที่คุณสร้างขึ้นเองจะใช้การเข้ารหัสแบบ RSA คุณต้องสร้างคีย์สาธารณะและคีย์ส่วนตัว
ผ่านซอฟต์แวร์ แล้วส่งเฉพาะคีย์สาธารณะให้ WaanX เท่านั้น เราจะไม่เก็บคีย์ส่วนตัวของคุณไว้เลย

> 1. ใช้ api-rsa-generator เพื่อสร้างคีย์ส่วนตัวและคีย์สาธารณะแบบ RSA
> 2. ทำตามสคริปต์ตัวอย่างของ RSA เพื่อดำเนินขั้นตอนการเข้ารหัสให้เสร็จสมบูรณ์

### HTTP header สำหรับเอนด์พอยต์ที่ต้องยืนยันตัวตน
ต้องใช้คีย์ HTTP header ต่อไปนี้ในการยืนยันตัวตน:

* `X-BAPI-API-KEY` - คีย์ API
* `X-BAPI-TIMESTAMP` - ประทับเวลา UTC หน่วยมิลลิวินาที
* `X-BAPI-SIGN` - ลายเซ็นที่คำนวณจากพารามิเตอร์ของคำขอ
* `X-Referer` or `Referer` - header สำหรับผู้ใช้ที่เป็นโบรกเกอร์เท่านั้น

เรายังมี `X-BAPI-RECV-WINDOW` (หน่วยเป็นมิลลิวินาที และค่าเริ่มต้นคือ 5,000) เพื่อระบุว่าคำขอ HTTP มีอายุใช้งานนานเท่าใด และยังใช้เพื่อป้องกันการโจมตีแบบ replay ด้วย

ค่า `X-BAPI-RECV-WINDOW` ที่เล็กลงจะปลอดภัยมากขึ้น แต่คำขอของคุณอาจล้มเหลวหากเวลาในการส่งข้อมูลมากกว่าค่า `X-BAPI-RECV-WINDOW` ของคุณ

:::caution
โปรดตรวจสอบว่าพารามิเตอร์ timestamp เป็นไปตาม**กฎต่อไปนี้**:<br/>
_server_time - recv_window <= timestamp < server_time + 1000_<br/>
ซึ่งหมายความว่า timestamp ของคุณต้องอยู่ในช่วง: [server_time - recv_window; server_time + 1000)<br/>
server_time หมายถึงเวลาของเซิร์ฟเวอร์ WaanX ซึ่งสามารถค้นหาได้ผ่าน[เอนด์พอยต์เวลาเซิร์ฟเวอร์](/v5/market/time#) โปรดทราบว่าเราแนะนำอย่างยิ่งให้ใช้เวลาของอุปกรณ์ในเครื่องสำหรับ `timestamp` และซิงโครไนซ์กับ NTP อยู่เสมอ
:::

### สร้างคำขอ

:::tip
เพื่อช่วยวินิจฉัยปัญหาเครือข่ายที่ซับซ้อน คุณอาจพิจารณาเพิ่ม `cdn-request-id` ใน header ของคำขอ โดยค่าดังกล่าวควรไม่ซ้ำกันในแต่ละคำขอ
:::

**ขั้นตอนพื้นฐาน:**
1. คำนวณสตริงที่คุณต้องการลงลายเซ็นดังนี้:
สำหรับคำขอ GET: timestamp + API key + recv_window + queryString
สำหรับคำขอ POST: timestamp + API key + recv_window + jsonBodyString
2. ใช้อัลกอริทึม <b>HMAC_SHA256</b> หรือ <b>RSA_SHA256</b> เพื่อลงลายเซ็นสตริงจากขั้นตอนที่ 1 แล้วแปลงเป็นสตริง HEX ตัวพิมพ์เล็กสำหรับ HMAC_SHA256 หรือเป็น base64 สำหรับ RSA_SHA256 เพื่อให้ได้ค่าสตริงของลายเซ็นของคุณ
3. เพิ่มลายเซ็นของคุณใน header `X-BAPI-API-KEY` แล้วส่งคำขอ HTTP คุณสามารถดูตัวอย่างด้านล่างเพื่อดูข้อมูลเพิ่มเติม

:::info
<b>ดูตัวอย่างอัลกอริทึมการลงลายเซ็นได้ที่นี่</b>
:::

## พารามิเตอร์การตอบกลับทั่วไป
| พารามิเตอร์ | ประเภท | คำอธิบาย|
|:----- |:-----|----- |
|retCode |number |รหัสสำเร็จ/ข้อผิดพลาด |
|retMsg |string |ข้อความสำเร็จ/ข้อผิดพลาด โดย `OK`, `success`, `SUCCESS`, `""` หมายถึงการตอบกลับที่สำเร็จ|
|result |Object |ผลลัพธ์ข้อมูลทางธุรกิจ|
|retExtInfo |Object |ข้อมูลเพิ่มเติม ส่วนใหญ่จะเป็น `{}`|
|time |number |ประทับเวลาปัจจุบัน (มิลลิวินาที)|

```json
{
    "retCode": 0,
    "retMsg": "OK",
    "result": {
    },
    "retExtInfo": {},
    "time": 1671017382656
}
```
