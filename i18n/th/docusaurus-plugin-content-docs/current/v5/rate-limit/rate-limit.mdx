## การจำกัดตาม IP
### การจำกัดตาม IP สำหรับ HTTP
โดยค่าเริ่มต้น คุณสามารถส่งได้ **600 คำขอภายในกรอบเวลา 5 วินาทีต่อหนึ่ง IP** ข้อจำกัดนี้ใช้กับทราฟฟิกทั้งหมดที่ส่งไปยัง `api.waanx.com`, `api.waanx.com` และชื่อโฮสต์ของไซต์ท้องถิ่น เช่น `api.waanx.com`
หากคุณพบข้อผิดพลาด **"403, access too frequent"** แสดงว่า IP ของคุณเรียกใช้บ่อยเกินความถี่ที่อนุญาต ในกรณีนี้ คุณควรยุติเซสชัน HTTP ทั้งหมดและรออย่างน้อย 10 นาที ระบบจะยกเลิกการระงับให้โดยอัตโนมัติ

เราไม่แนะนำให้เรียกใช้แอปพลิเคชันของคุณที่ระดับใกล้เคียงกับขีดจำกัดเหล่านี้ เพราะกิจกรรมเครือข่ายที่ผิดปกติ
อาจทำให้เกิดการละเมิดขีดจำกัดโดยไม่คาดคิดได้

### การจำกัดตาม IP สำหรับ WebSocket
* อย่าสร้างการเชื่อมต่อเกิน 500 การเชื่อมต่อภายในกรอบเวลา 5 นาที ข้อจำกัดนี้ใช้กับการเชื่อมต่อทั้งหมดที่ส่งไปยัง `stream.waanx.com` รวมถึงชื่อโฮสต์ของไซต์ท้องถิ่น เช่น `stream.waanx.com`
* อย่าเชื่อมต่อและตัดการเชื่อมต่อบ่อยครั้ง
* อย่าสร้างการเชื่อมต่อเกิน 1,000 การเชื่อมต่อต่อหนึ่ง IP สำหรับข้อมูลตลาด

## การจำกัดอัตราการเรียก API
:::caution
หากคุณได้รับ `"retCode": 10006, "retMsg": "Too many visits!"` ในการตอบกลับแบบ JSON แสดงว่าคุณเรียกใช้เกินการจำกัดอัตราการเรียก API แล้ว
:::
การจำกัดอัตราการเรียก API คิดตาม**กรอบเวลาแบบเลื่อนต่อวินาทีและต่อ UID** กล่าวคือ เป็นการนับต่อวินาทีต่อหนึ่ง UID
ทุกคำขอที่ส่งไปยัง API จะคืนค่าเฮดเดอร์ของการตอบกลับตามที่แสดงในแผงโค้ด:
* `X-Bapi-Limit-Status` - จำนวนคำขอที่คุณเหลือสำหรับเอนด์พอยต์ปัจจุบัน
* `X-Bapi-Limit` - ขีดจำกัดปัจจุบันของคุณสำหรับเอนด์พอยต์ปัจจุบัน
* `X-Bapi-Limit-Reset-Timestamp` - ประทับเวลาที่ระบุว่าขีดจำกัดคำขอของคุณจะรีเซ็ตเมื่อใด ในกรณีที่คุณเรียกใช้เกิน rate_limit หากไม่เกิน ค่านี้จะเป็นเพียงประทับเวลาปัจจุบัน (ซึ่งอาจไม่ตรงกับ `timeNow` เสมอ)

> ตัวอย่างเฮดเดอร์การตอบกลับ HTTP

```http
▶Response Headers
Content-Type: application/json; charset=utf-8
Content-Length: 141
X-Bapi-Limit: 10
X-Bapi-Limit-Status: 9
X-Bapi-Limit-Reset-Timestamp: 1672738134824
```

## คำอธิบายสำหรับเอนด์พอยต์แบบกลุ่ม {#instructions-for-batch-endpoints}
:::tip
เอนด์พอยต์คำสั่งซื้อขายแบบกลุ่ม ซึ่งครอบคลุมการสร้าง การแก้ไข และการยกเลิก มีการจำกัดอัตราการเรียกเป็นของตัวเอง และ
ไม่ได้แบ่งใช้ร่วมกับคำขอแบบรายการเดียว *ตัวอย่างเช่น สมมติว่าการจำกัดอัตราการเรียกของเอนด์พอยต์สร้างคำสั่งซื้อขายแบบรายการเดียวคือ 100/s และเอนด์พอยต์สร้างคำสั่งซื้อขายแบบกลุ่ม
คือ 100/s ในกรณีนี้ ฉันจะสามารถสร้างคำสั่งซื้อขายได้ 200 รายการในหนึ่งวินาที หากใช้ทั้งสองเอนด์พอยต์ในการสร้างคำสั่งซื้อขาย*

- สำหรับ API สร้าง/แก้ไข/ยกเลิกคำสั่งซื้อขายแบบกลุ่ม ความถี่ของ API จะเป็นไปตามการตั้งค่าปัจจุบัน
แต่การนับปริมาณที่ใช้ไปจะคิดตามจำนวนคำสั่งซื้อขายที่เกิดขึ้นจริง (จำนวนที่ใช้ไป = จำนวน
คำขอ * จำนวนคำสั่งซื้อขายที่รวมอยู่ในหนึ่งคำขอ) และการตั้งค่าของแต่ละสายธุรกิจนั้นแยกจากกันโดยอิสระ

- API แบบกลุ่มอนุญาตให้ส่งได้ 1-10 คำสั่งต่อหนึ่งคำขอ ตัวอย่างเช่น หากส่งคำขอคำสั่งซื้อขายแบบกลุ่มหนึ่งครั้งซึ่งมี 5 คำสั่ง
ระบบจะนับว่าใช้ขีดจำกัดคำขอไป 5 หน่วย

- หากคำสั่งซื้อขายกลุ่มสุดท้ายที่ส่งเข้ามาภายใน 1 วินาทีมีส่วนที่เกินขีดจำกัด ส่วนที่เกินขีดจำกัดจะล้มเหลว และ
ส่วนที่ไม่เกินขีดจำกัดจะสำเร็จ ตัวอย่างเช่น ในวินาทีนั้น ขีดจำกัดคงเหลือคือ 5 แต่มีการส่งคำขอแบบกลุ่ม
ที่มี 8 คำสั่งเข้ามาในขณะนั้น คำสั่ง 5 รายการแรกจะถูกสร้างสำเร็จ ส่วนคำสั่งรายการที่ 6-8
จะแจ้งข้อผิดพลาดว่าเกินขีดจำกัด และคำสั่งเหล่านั้นจะล้มเหลว
