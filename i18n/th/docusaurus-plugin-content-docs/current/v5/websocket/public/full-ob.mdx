สมัครรับข้อมูลสตรีมสมุดคำสั่งซื้อขายแบบเต็ม ส่งเฉพาะการอัปเดต**ส่วนต่างเท่านั้น** สำหรับข้อมูลตลาดที่มีความลึกแบบเต็ม

> **ครอบคลุม: สปอต**

:::info
* คำสั่งซื้อขาย [Retail Price Improvement (RPI)](https://support.waanx.com/en/support/home) จะไม่รวมอยู่ในข้อความที่ส่งมา
* สตรีมนี้ส่งเฉพาะ**การอัปเดตส่วนต่างเท่านั้น** โดยไม่มีข้อความสแนปช็อตเริ่มต้น คุณต้องกำหนดค่าเริ่มต้นให้สมุดคำสั่งซื้อขายในเครื่องของคุณด้วย[สแนปช็อตสมุดคำสั่งซื้อขายแบบเต็มผ่าน REST](../../market/full-ob) ก่อนที่จะนำส่วนต่างไปใช้
:::

### ความถี่ในการส่งข้อมูล

**สปอต:**<br/>
ข้อมูลความลึกแบบเต็ม ความถี่ในการส่งข้อมูล: **200ms**<br/>

**หัวข้อ:**<br/>
`orderbook.full.{symbol}` เช่น `orderbook.full.BTCUSDT`

:::info สถานการณ์ที่เกิดการรีเซ็ต (`u=1`)

| สถานการณ์ | เพย์โหลด WS | สแนปช็อต REST | สิ่งที่ไคลเอนต์ต้องทำ |
|:---------|:-----------|:--------------|:--------------|
| รีสตาร์ตบริการ | `u=1` | `u` อาจรีเซ็ตเป็น `1` ได้เช่นกัน | เขียนทับสมุดคำสั่งซื้อขายในเครื่องด้วยสแนปช็อต |
| ถอดสัญลักษณ์คู่เทรดออกจากรายการ | `u=1`, `b=[]`, `a=[]` | คืนค่าว่าง | ล้างสมุดคำสั่งซื้อขายในเครื่อง และทำเครื่องหมายว่า**ไม่พร้อมใช้งาน** |
| ก่อนการประมูลช่วงพรีมาร์เก็ต | `u=1`, ส่วนต่างว่าง | อาจคืนค่าว่าง | คงสมุดคำสั่งซื้อขายให้ว่างไว้ และถือว่าเป็น **NO_BOOK** |
| การประมูล → การเทรดต่อเนื่อง | `u=1`, ส่วนต่างว่าง | คืนค่าสแนปช็อตที่ใช้ได้ | ดึงสแนปช็อต แล้วดำเนินการต่อด้วยส่วนต่าง |
| การเปลี่ยนการตั้งค่า lot / tick | `u=1`, ส่วนต่างอาจว่างได้ | สแนปช็อตพร้อมใช้เมื่อเหมาะสม | ล้างและซิงค์สมุดคำสั่งซื้อขายในเครื่องใหม่ |

:::

### ขั้นตอนการซิงโครไนซ์สมุดคำสั่งซื้อขายแบบเต็ม
ใช้เอนด์พอยต์ REST เพื่อดึงสแนปช็อตสมุดคำสั่งซื้อขาย (OB) แล้วสมัครรับข้อมูลการอัปเดตส่วนต่างของ OB ผ่าน WebSocket เพื่อรักษาสมุดคำสั่งซื้อขายในเครื่องให้สมบูรณ์ ทั้งข้อความสแนปช็อต OB และข้อความส่วนต่าง OB จะมีสองฟิลด์ คือ `seq` และ `u` สำหรับการจับคู่ข้อมูลและการจัดลำดับ

* `seq`: หมายเลขเวอร์ชันของระบบจับคู่คำสั่ง ค่านี้เพิ่มขึ้นแบบทางเดียว แต่ไม่รับประกันว่าจะต่อเนื่องกัน แพ็กเก็ตส่วนต่างที่อยู่ติดกันของสัญลักษณ์คู่เทรดเดียวกันอาจมีค่า `seq` ที่ไม่ต่อเนื่องกันได้
* `u`: รหัสการอัปเดต ค่านี้ต่อเนื่องกัน โดยค่า `u` ของแพ็กเก็ตส่วนต่างแต่ละชุดจะเพิ่มขึ้นหนึ่งค่าจากชุดก่อนหน้า (`u+1`) อย่างไรก็ตาม เมื่อระบบรีสตาร์ตหรือมีการปรับ tick size ค่า `u` จะรีเซ็ตเป็น `1` และเริ่มนับหมายเลขส่วนต่างใหม่

1. เปิดการเชื่อมต่อ WebSocket ข้อมูลตลาด และสมัครรับข้อมูลช่องสมุดคำสั่งซื้อขายแบบความลึกเต็ม
2. เก็บส่วนต่างทั้งหมดที่ได้รับจากสตรีมไว้ในบัฟเฟอร์ โดยบันทึกค่า `seq` และ `u` ของส่วนต่างชุดแรกไว้
  - หากตรวจพบว่า `u` ไม่ต่อเนื่อง ให้ล้างบัฟเฟอร์และเริ่มเก็บบัฟเฟอร์ใหม่
  - หากตรวจพบว่า `seq` ลดลง ให้ทิ้งแพ็กเก็ตส่วนต่างนั้น
3. ดึง[สแนปช็อตสมุดคำสั่งซื้อขายแบบความลึกเต็ม](../../market/full-ob)จากเอนด์พอยต์ REST
4. เปรียบเทียบ `seq` และ `u` ของสแนปช็อตกับส่วนต่างที่เก็บไว้ในบัฟเฟอร์:
  - หาก `seq` ของสแนปช็อตน้อยกว่า `seq` ของส่วนต่างชุดแรกในบัฟเฟอร์ ให้ทำขั้นตอนที่ 3 ซ้ำจนกว่าจะได้สแนปช็อตที่ใหม่เพียงพอ
  - ในบรรดาส่วนต่างที่เก็บไว้ในบัฟเฟอร์ ให้ทิ้งส่วนต่างทั้งหมดที่มี `seq` น้อยกว่า `seq` ของสแนปช็อต
  - หาก `seq` ของสแนปช็อตเท่ากับ `seq` ของส่วนต่าง แต่ค่า `u` ต่างกัน ให้ทำขั้นตอนที่ 3 ซ้ำจนกว่าจะได้สแนปช็อตที่ใหม่เพียงพอ
5. เมื่อ `seq` และ `u` ของสแนปช็อตตรงกับ `seq` และ `u` ของส่วนต่างแล้ว ให้กำหนดค่าเริ่มต้นสมุดคำสั่งซื้อขายในเครื่องด้วยสแนปช็อตนั้น และตั้งค่าเวอร์ชันของสมุดคำสั่งซื้อขายในเครื่องเป็นค่า `u` ของสแนปช็อต
7. นำส่วนต่างที่เหลือในบัฟเฟอร์ทั้งหมดไปใช้กับสมุดคำสั่งซื้อขายในเครื่องตามที่อธิบายด้านล่าง แล้วดำเนินการประมวลผลส่วนต่างแบบเรียลไทม์ต่อไป

#### ขั้นตอนการอัปเดตสมุดคำสั่งซื้อขาย

สำหรับอีเวนต์ส่วนต่างแต่ละรายการที่เข้ามา:

1. ตรวจสอบความต่อเนื่องของอีเวนต์

* หาก `u` ของอีเวนต์น้อยกว่า `u` ของสมุดคำสั่งซื้อขายในเครื่อง ให้ละเว้นอีเวนต์นั้น
* หาก `u` ของอีเวนต์มากกว่า `u` ของสมุดคำสั่งซื้อขายในเครื่อง + 1 หมายความว่ามีอีเวนต์ตกหายไปหนึ่งรายการหรือมากกว่า ในกรณีนี้:
    * ให้ทิ้งสมุดคำสั่งซื้อขายในเครื่อง
    * เริ่มกระบวนการซิงโครไนซ์ใหม่ตั้งแต่ต้น
* ในสภาวะปกติ ค่า u ของอีเวนต์ถัดไปควรเท่ากับค่า u ของอีเวนต์ก่อนหน้า + 1
* หาก `u` ของอีเวนต์ = 1 ให้เริ่มขั้นตอนการซิงค์ใหม่

2. นำการอัปเดตระดับราคาไปใช้

สำหรับทุกระดับราคาในฝั่งซื้อ (b) และฝั่งขาย (a):

* หากระดับราคานั้นยังไม่มีอยู่ในสมุดคำสั่งซื้อขายในเครื่อง ให้เพิ่มเข้าไปด้วยจำนวนที่ระบุ
* หากจำนวนเป็นศูนย์ ให้ลบระดับราคานั้นออกจากสมุดคำสั่งซื้อขายในเครื่อง
* หากไม่เข้าเงื่อนไขข้างต้น ให้อัปเดตจำนวนของระดับราคาที่มีอยู่

:::info
เอนด์พอยต์สแนปช็อต REST จะคืนค่าระดับราคาได้สูงสุด 10,000 ระดับต่อฝั่ง ด้วยเหตุนี้ ระดับราคาที่อยู่นอกช่วงของสแนปช็อต 
เริ่มต้นจึงไม่เป็นที่ทราบ เว้นแต่จะปรากฏในการอัปเดตส่วนต่างในภายหลัง

ดังนั้น จำนวนของระดับราคาที่อยู่เกินความลึกของสแนปช็อตอาจไม่ได้สะท้อนสถานะที่สมบูรณ์ของสมุดคำสั่งซื้อขาย อย่างไรก็ตาม สำหรับกรณีการใช้งานด้าน 
การเทรดและการวิเคราะห์ตลาดส่วนใหญ่ ความลึกที่มีให้ (โดยทั่วไปมากกว่า 10,000 ระดับต่อฝั่ง) ก็เพียงพอที่จะให้มุมมองที่ 
แม่นยำเกี่ยวกับสภาพคล่องของตลาดและสภาวะการเทรด
:::
