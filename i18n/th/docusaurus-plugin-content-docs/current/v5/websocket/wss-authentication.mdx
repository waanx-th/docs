:::tip ปรับแต่งระยะเวลาคงการเชื่อมต่อส่วนตัว
สำหรับสตรีมส่วนตัวและการส่งคำสั่งซื้อขาย คุณสามารถปรับแต่งระยะเวลาคงการเชื่อมต่อได้โดยเพิ่มพารามิเตอร์ `max_active_time` ค่าต่ำสุดคือ `30s` (30 วินาที) ค่าสูงสุดคือ `600s` (10 นาที) คุณยังสามารถส่งค่าเป็น `1m`, `2m` เป็นต้น เมื่อต้องการตั้งค่าในระดับนาที เช่น <i>wss://stream.waanx.com/v5/private?max_active_time=1m</i>

โดยทั่วไป หากไม่มี "ping-pong" และไม่มีข้อมูลสตรีมที่ส่งมาจากฝั่งเซิร์ฟเวอร์ การเชื่อมต่อจะถูกตัดหลังจาก 10 นาที เมื่อคุณมีความต้องการเฉพาะ คุณสามารถกำหนดระยะเวลาคงการเชื่อมต่อได้ด้วย `max_active_time`

เนื่องจากทิกเกอร์จะตรวจสอบทุก 30 วินาที ค่านี้จึงไม่แม่นยำทั้งหมด กล่าวคือ หากคุณตั้งค่าเป็น 45 วินาที และการอัปเดตหรือ ping-pong ครั้งล่าสุดของคุณเกิดขึ้นเมื่อ `2023-08-15 17:27:23` เวลาตัดการเชื่อมต่อของคุณอาจเกิดขึ้นเมื่อ `2023-08-15 17:28:15`
:::

## การยืนยันตัวตน {#authentication}
:::info
หัวข้อ<b>สาธารณะ</b>ไม่จำเป็นต้องยืนยันตัวตน ส่วนต่อไปนี้ใช้กับหัวข้อ<b>ส่วนตัว</b>เท่านั้น
:::

<p>ขอยืนยันตัวตนเมื่อสร้างการเชื่อมต่อ</p>
<p>หมายเหตุ: หากคุณใช้ไลบรารีไคลเอนต์ระดับสูง คุณสามารถข้ามโค้ดนี้ได้เมื่อไลบรารีจัดการการยืนยันตัวตนให้คุณแล้ว</p>

```json
{
    "req_id": "10001", // optional
    "op": "auth",
    "args": [
        "api_key",
        1662350400000, // expires; is greater than your current timestamp
        "signature"
    ]
}
```



> ตัวอย่างการตอบกลับเมื่อยืนยันตัวตนสำเร็จ

```json
{
    "success": true,
    "ret_msg": "",
    "op": "auth",
    "conn_id": "cejreaspqfh3sjdnldmg-p"
}
```

:::note
ตัวอย่างอัลกอริทึมการสร้างลายเซ็นสามารถดูได้ที่นี่
:::

:::caution
เนื่องจากความซับซ้อนของเครือข่าย คุณอาจถูกตัดการเชื่อมต่อได้ตลอดเวลา โปรดปฏิบัติตามคำแนะนำด้านล่างเพื่อให้แน่ใจว่าคุณจะได้รับข้อความ WebSocket ตรงเวลา:
1. คงการเชื่อมต่อไว้โดย[ส่งแพ็กเก็ตฮาร์ตบีต](connect#how-to-send-the-heartbeat-packet)
2. เชื่อมต่อใหม่โดยเร็วที่สุดหากถูกตัดการเชื่อมต่อ
:::

## การจำกัดตาม IP
* อย่าเชื่อมต่อและตัดการเชื่อมต่อบ่อยครั้ง
* อย่าสร้างการเชื่อมต่อเกิน 500 การเชื่อมต่อภายใน 5 นาที ข้อจำกัดนี้นับแยกตามโดเมนของ WebSocket

## ช่องทางสาธารณะ - ข้อจำกัดของ args
สำหรับการเชื่อมต่อสาธารณะหนึ่งการเชื่อมต่อ ความยาวของอาร์เรย์ "args" ต้องไม่เกิน 21,000 อักขระ
* สปอตสามารถระบุ args ได้สูงสุด 10 รายการต่อคำขอสมัครรับข้อมูลหนึ่งคำขอที่ส่งไปยังการเชื่อมต่อหนึ่งการเชื่อมต่อ

## วิธีส่งแพ็กเก็ตฮาร์ตบีต {#how-to-send-the-heartbeat-packet}

> วิธีการส่ง

```javascript
// req_id is a customised ID, which is optional
ws.send(JSON.stringify({"req_id": "100001", "op": "ping"}));
```

> ตัวอย่างข้อความ pong ของช่องทางสาธารณะ

```json
{
    "success": true,
    "ret_msg": "pong",
    "conn_id": "0970e817-426e-429a-a679-ff7f55e0b16a",
    "op": "ping"
}
```

> ตัวอย่างข้อความ pong ของช่องทางส่วนตัว

```json
{
    "req_id": "test",
    "op": "pong",
    "args": [
        "1675418560633"
    ],
    "conn_id": "cfcb4ocsvfriu23r3er0-1b"
}
```

:::caution
เพื่อหลีกเลี่ยงปัญหาเครือข่ายหรือปัญหาของโปรแกรม เราแนะนำให้คุณส่งแพ็กเก็ตฮาร์ตบีต <code>ping</code> ทุก <b>20</b> วินาที เพื่อรักษาการเชื่อมต่อ WebSocket
:::

## วิธีสมัครรับข้อมูลหัวข้อ
### ทำความเข้าใจฟิลเตอร์ของ WebSocket

วิธีสมัครรับข้อมูลด้วยฟิลเตอร์

```json
// Subscribing level 1 orderbook
{
    "req_id": "test", // optional
    "op": "subscribe",
    "args": [
        "orderbook.1.BTCUSDT"
    ]
}
```

รองรับการสมัครรับข้อมูลด้วยสัญลักษณ์คู่เทรดและหัวข้อหลายรายการ

```json
{
    "req_id": "test", // optional
    "op": "subscribe",
    "args": [
        "orderbook.1.BTCUSDT",
        "publicTrade.BTCUSDT",
        "orderbook.1.ETHUSDT"
    ]
}
```

### ทำความเข้าใจฟิลเตอร์ของ WebSocket: การยกเลิกการรับข้อมูล

คุณสามารถสมัครรับข้อมูลและยกเลิกการรับข้อมูลของหัวข้อได้แบบไดนามิก โดยไม่ต้องยกเลิกการรับข้อมูลจาก WebSocket ดังนี้:

```json
{
    "op": "unsubscribe",
    "args": [
        "publicTrade.ETHUSD"
    ],
    "req_id": "customised_id"
}
```
